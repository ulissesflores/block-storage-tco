# ADR-001 — What this repository publishes, and what it deliberately does not

- **Status:** accepted
- **Date:** 2026-08-15
- **Context:** companion repository to an academic case study that is submitted, not published here

## Context

The study behind this repository produces two things: a **written article**, which is submitted to
an institution as assessed coursework, and a **body of evidence and computation** — captured prices,
capture and analysis code, tests, derived tables and figures — which has no reason to be private and
every reason to be auditable.

Publishing the second while withholding the first is not a compromise; it is the correct division.
Evidence that cannot be inspected is a claim about the author's diligence. An assessed text that is
deposited publicly by its own author is a different kind of object, and one this repository has no
interest in being.

## Decision

**Everything that evidences or reproduces goes in. Only the article itself stays out.**

### In

| What | Why |
|---|---|
| 46 raw price bodies (`data/precos/`) and 4 raw HTML pages (`data/evidencia/`) | the evidence; byte-identical to the sealed copies |
| Capture code (`capture_prices`, `run_capture`, `capture_manual`, `catalogo`) | the request path must be auditable, not described |
| Analysis code (`tco`, `filas`, `sensibilidade_membros`, `figuras`, `freeze_env`) | the arithmetic that turns prices into a verdict |
| Configuration (case specification, load assumptions, technical design, amendments, chain stages) | the model's inputs; without them nothing runs |
| 16 derived CSV files and 5 figures | the results, each regenerated by the published code |
| Tests | every published number is an assertion |
| Integrity layer (`make_provenance.py`, `checksums.sha256`, `PROVENANCE.md`, chain ledger) | the audit report |

### Out

| What | Why |
|---|---|
| The article (PDF, DOCX, Markdown source) | it is assessed coursework, submitted to an institution; the author does not deposit it publicly |
| The rendered body tables (`corpo-tabela-*.csv`, `apendice-a-*.csv`) and their generator | those files are the article's tables, prose notes included — they are text, not evidence. The numbers behind them are published in the model's own output (`tco-por-item.csv`, `dimensionamento.csv`, `precos-unitarios.csv`) |
| The figure captions (`legendas()` in `figuras.py`, `LEGENDAS-FIGURAS.md`) | captions are paragraphs of the article body. The figures themselves are published |
| The paper toolchain (`export_docx.py`, `gates_paper.py`, `tabelas_paper.py`, `build_run.py`) | it produces or seals the article, not the evidence |
| The `manifest.json` files of the sealed runs | they record absolute paths on the author's machine. Their contents are published as hashes in `docs/chain-ledger.tsv` |
| The pre-registration in its original Portuguese | rendered in English as `PREREGISTRATION.md`, with the sealed original's SHA-256 cited so the correspondence can be checked by anyone who obtains it |
| The account-security plan inside the technical design | prose from the article body; no published module reads it |

### Consequences accepted

1. **The code published here is not bit-identical to the code that produced the sealed results.**
   Thirteen files differ, each listed in `PROVENANCE.md` with both digests and a reason. The identity
   claim is therefore made over `data/` — where it holds exactly — and never over `src/`.
2. **The `User-Agent` divergence is the sharpest case and is stated first.** The header actually sent
   on 2026-08-13 carried the course identifier; the public copy renames it. Anyone re-running the
   capture sends a different header than the one that produced the frozen bodies. That is a real
   difference, it is declared, and it is the reason the byte-for-byte claim is scoped to the captured
   bodies rather than to the capture client.
3. **The public test suite is smaller than the internal one.** 24 cases were dropped because they
   assert properties of artefacts that are not published — the article text, its rendered tables, its
   captions. Nineteen new cases were added that only make sense here: the integrity layer and the
   headline numbers of the README. What remains covers every number this repository publishes.
4. **The figures are published even though three of them are also pages of the article.** This was a
   deliberate call by the author: a figure generated by code, from data that is published, is
   evidence a reader can regenerate — and withholding it would weaken the repository to protect
   something the captions and the surrounding text already keep out.

## Alternatives rejected

- **Publish nothing until the article is assessed.** Rejected: the repository's value is that it can
  be inspected alongside the work, and delaying it adds no protection that the scope rule does not
  already give.
- **Publish the article behind a password printed in the document.** Rejected: the deposit would
  still be public, permanent and dated, and the only thing a password would actually defeat is an
  automated check — which is not a legitimate goal.
- **Publish the rendered tables because they are convenient.** Rejected: they carry prose notes that
  belong to the article. The underlying numbers are published in machine-readable form instead, which
  is more useful and less confused about what it is.
